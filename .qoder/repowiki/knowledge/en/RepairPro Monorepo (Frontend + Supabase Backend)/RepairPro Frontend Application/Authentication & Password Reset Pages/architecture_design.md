Three sibling React page components under `src/pages/` that together implement the full authentication surface:
- `Auth.tsx` is the entry point for both owner (shop) and employee sign-in/sign-up. It owns local form state, role selection (`owner` | `employee`), tab switching (`login` | `register`), and integrates with `@/contexts/AuthContext` (`signIn`, `signUp`, `user`) and direct `supabase.auth` calls. After login it resolves roles from `user_roles` and team membership in `team_members` to enforce owner/employee tab guards, checks `profiles.is_locked`, then navigates to `/dashboard` (with a 3D BlueprintLoader animation for owners) or a `redirect` query param.
- `ResetPassword.tsx` implements a four-step wizard (`request` → `code` → `password` → `done`) driven by a `Step` state machine. It calls Supabase Edge Functions `request-reset-code`, `verify-reset-code`, and `update-password-with-token` (the last one gated by a short-lived token passed via `Authorization: Bearer <token>`). A 60-second resend cooldown and an `OtpInput` component are used.
- `UpdatePassword.tsx` handles the email-link recovery path: it parses hash/query params, exchanges a PKCE code via `supabase.auth.exchangeCodeForSession`, listens for `PASSWORD_RECOVERY` auth events, and on success calls `update-password-with-token` with a `reset_token` stored in `sessionStorage`.

All three pages depend outward on shared UI primitives (`@/components/ui/*`), `@/integrations/supabase/client`, `@/contexts/AuthContext`, and `@/components/seo/SEO`; they never import each other, keeping each route self-contained. Business rules (rate limiting, CAPTCHA guard, trial grant, admin notification) are delegated to Supabase Edge Functions rather than implemented client-side.
