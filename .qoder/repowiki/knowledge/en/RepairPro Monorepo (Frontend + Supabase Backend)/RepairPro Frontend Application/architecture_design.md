The module is organized as a feature-sliced React/Vite app: `pages/` declares top-level routes consumed by the app shell (`App.tsx`, `main.tsx`), which mounts providers from `contexts/` (Auth, ShopSettings, Notifications, Impersonation, BrandTheme) and lazy-loads page modules. Feature domains are split into sibling folders under `components/` (admin, auth, billing, customers, inventory, repairs, returns, services, settings, team, etc.) that consume domain-specific hooks in `hooks/` (e.g. `useCustomers`, `useRepairs`, `useAdminOrders`) which wrap Supabase client calls defined in `integrations/supabase/`. Cross-cutting concerns live in `lib/` (query keys, currency, PDF/receipt generation, fingerprinting, SW updates) and `i18n/` for multi-language strings consumed via `components/i18n/`. The service worker (`sw.ts`) is registered by the shell to enable offline caching, while `test/` holds unit tests for shared utilities.
